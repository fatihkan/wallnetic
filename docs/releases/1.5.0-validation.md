# Wallnetic 1.5.0 — collective validation checklist

The checks for the collective validation session in #312. Run every check once,
on the release candidate. Fix failures, then re-check only what changed; do not
repeat the whole session.

- **T01–T39** come from the local test notes of October 2026.
- **R01–R12** are the release scenarios in #312.
- **W01–W20** cover the remaining physical, VoiceOver, multi-display and
  lifecycle criteria of the wave issues.
- **M01–M10** are the measurements of #255.

[Coverage by issue](#coverage-by-issue) lists the checks for each issue.

## Before the session

**Release candidate.** Build 1.5.0 (12) from c80fffb, not a Debug build. It
is the universal Release archive in the App Store configuration:

- sandbox, App Group and hardened runtime on;
- app and widget both 1.5.0 (12);
- strict signature verification passes.

Run it in one of two ways, and record which:

- from TestFlight, where build 12 is the distribution-signed upload of that
  archive;
- or from the development-signed archive itself, on a Mac in its provisioning
  profile.

Both contain the same binary. It uses the same app identity and data as an
installed Wallnetic. Installing from TestFlight replaces the App Store copy for
every user account on that Mac. For R08, set up 1.4.2 first and install the
release candidate afterwards.

**Machines.** Record which of these took part. A check that needs a missing
machine is reported as untested in its issue, never as passed.

| Machine | Checks |
| --- | --- |
| Apple silicon Mac on macOS 26 with two displays | Every check |
| macOS 27 | T01–T09, and the current-macOS runs of W05 and W17 |
| macOS 13 | W05 and W17, plus launch, onboarding, Settings and playback in both renderers |
| Intel Mac | T08, T12, T13, W16, M01 |
| A second Apple silicon model | M01 |
| A Mac with a battery | W02, the battery part of W08, M06 |
| An HDR-capable display | R07, the HDR part of W11 |
| Displays with different scale factors | W19 |

Without a macOS 27 Mac, run the current-macOS checks on macOS 26 and record the
version. A macOS 13 virtual machine on Apple silicon can stand in for launch,
onboarding, Settings and playback only. Label those results as VM results: they
are no evidence for performance, hardware decoding, HDR, displays or sleep.

**Media.** Import copies through the app; never move or rename real Library
files.

- The welcome tour's sample, `src/Wallnetic/Resources/Samples/AuroraSample.mp4`.
- The benchmark fixtures (`benchmark.py fixtures`, see
  [PLAYBACK_BENCHMARKS.md](../PLAYBACK_BENCHMARKS.md)): 1080p H.264 and 2160p
  60 fps HEVC.
- Videos in 16:9, 9:16 and 21:9.
- A phone video: portrait or rotated, HEVC, variable frame rate.
- HDR videos: PQ, HLG, and one rotated HDR video.
- A video several minutes long, so a conversion can be cancelled in time.
- A video with a long Turkish name containing combining accents or emoji.
- H.264 and HEVC videos at least 20 seconds long, for trims whose Start is not
  a keyframe.

**Preparation.**

1. Note your playback, display, schedule, playlist and power settings, and
   restore them at the end.
2. Delete only copies imported for the test. Never select the whole Library.
3. For plain playback checks, turn off Schedule, Playlist, Calm Mode and Pause
   After. Record any pause reason that Settings > Display still shows.
4. Run sections 1–6 first, starting with T01–T09. Section 7 is a separate pass.

## Recording results

Record once per session:

- machine label (no serial numbers), macOS version and build;
- displays: count, model, resolution, scale, refresh rate, HDR, arrangement;
- renderer, playback profile and power source (AC, battery, Low Power Mode);
- the release candidate's version and commit.

Record each check as **Pass**, **Fail**, **Not run** or **N/A**, per renderer
where it runs in both. A step that was not tried is Not run, never Pass. If only
part of a check ran, say which part. Post the results to #312 and to the issues
the check names.

Report a failure like this:

```text
Check:
Result:
Time:
Machine, macOS, displays:
Renderer, profile, power:
Video (file name, codec, resolution):
Pause After, Calm Mode, manual pause:
Steps:
Expected:
Observed:
How often:
Screenshot, recording or crash report:
```
